# Human-Crafted Slides — 사람이 편집한 듯한 프레젠테이션

## 목적과 적용 원칙

- 이 스킬의 목적은 **AI 사용 사실을 숨기는 것**이 아니라, 자동 생성 PPT에서 흔히 보이는 상투적인 시각적·언어적 패턴을 피하고 **내용에 맞게 편집된 좋은 발표자료**를 만드는 것이다. AI 활용 사실의 공개가 요구되는 상황에서는 그 요구를 따른다.
- 적용 대상: PPTX 새 제작, 기존 PPT 재디자인, 발표자료 기획·스토리보드, 슬라이드 시각 품질 검수. 결과물이 문서나 온라인 슬라이드여도 발표자료 디자인 원칙은 동일하게 적용한다.
- **우선순위:** 사용자의 명시적 요구·제공된 브랜드 가이드·기존 템플릿·원본 사실 > 이 스킬의 기본 스타일. 사용자가 요청한 디자인 요소를 일률적으로 금지하지 않는다.
- 내용의 정확성과 발표 목적을 장식적 세련미보다 우선한다. 단순한 'AI 티 없애기'를 명목으로 의도적인 오류, 어색한 비대칭, 위장 출처 등을 만들지 않는다.
- 이 스킬은 **디자인과 제작 워크플로**를 보완한다. 별도의 PPTX 생성·편집 도구가 있으면 그것을 사용하며, SKILL.md만으로 렌더링 기능이나 도구가 새로 생기지는 않는다.

## 실행 순서: 반드시 이 흐름을 따른다

### 1. 과제를 이해하고 디자인 범위를 정한다

1. 목적(무엇을 알게/하게 할 것인가), 청중, 발표 환경, 언어, 예상 시간, 최종 형식(PPTX/PDF/기획안), 슬라이드 수를 기존 요청에서 파악한다.
2. 주제, 원본 문서, 이미지, 참조 PPT, 디자인 레퍼런스가 제공되었다면 **먼저 실제로 확인**한다. 제공되지 않은 내용을 본 것처럼 말하지 않는다.
3. 부족한 정보는 목적에 맞는 합리적인 기본값으로 보완한다. 사소한 디자인 선택마다 질문하지 않는다. 내용의 정확성이나 핵심 산출 형식이 달라질 때만 꼭 필요한 질문을 한다.
4. 기존 PPT/브랜드가 있으면 그 색상·서체·정렬·레이아웃을 추출해 디자인 시스템으로 삼는다. 새로 만드는 개인용 발표자료라면 기본값은 **Technical Manual + Editorial + Information Design**으로 한다.
5. 실제 PPTX 제작 요청이면 가능한 도구로 **실제 산출물을 제작**한다. 사용자가 기획만 요청했을 때만 스토리보드로 마친다.

### 2. 디자인에 앞서 논리와 자료를 편집한다

- 전체를 관통하는 **한 문장 결론**을 먼저 정한다. 청중의 질문 또는 문제 → 구체적 관찰·증거 → 원리·방법 → 시연·적용 → 요약·다음 행동을 기본 흐름으로 쓰되 강제하지 않는다.
- 각 장에 `slide_id / purpose / takeaway / title / evidence / visual_type / sources / speaker_notes`를 지정한 스토리보드를 만든다. 각 장은 명확한 핵심 주장을 갖되, 이를 뒷받침하는 표·사례·설명 여러 개는 가능하다.
- 제목은 필요할 때 주제명보다 **메시지형 주장**으로 쓴다. 단, 장 구분·용어 설명·실습 안내에서는 간결한 명사형 제목도 허용한다.
- 추상적인 미사여구(혁신, 무한한 가능성, 패러다임, 시너지) 대신 **검증 가능한 구체적인 행동·자료·결과**를 설명한다.
- 실제 강연자의 수업 사례, 현장 문제, 실습 화면, 원문 인용이 있다면 일반적인 스톡 예시보다 우선한다.
- 출처 없는 수치, 연구, 발언, 사례, 제품 UI를 **지어내지 않는다**. 확인 불가한 핵심 정보는 `[자료 확인 필요]`로 표시하고 최종 전달 시 알려준다.
- 그림과 사진의 원본 출처·라이선스·인용 맥락을 확인한다. 학교 자료 등에는 개인 정보·학생 초상·민감 정보가 노출되지 않게 처리한다.

### 3. 슬라이드용 디자인 시스템을 설정한다

스타일을 매번 무작위로 결정하지 말고 아래 기본값에서 출발한다. 사용자가 레퍼런스를 제공하면 우선 그 레퍼런스에서 규칙을 추출한다.

| 항목 | 기본 규칙 |
| --- | --- |
| 비율 | 16:9 와이드스크린. 지정된 비율이 있다면 우선 적용 |
| 배경 | 흰색 `#FFFFFF` 또는 명시된 브랜드 배경 |
| 글자색 | 기본 `#202124`, 보조 `#667085` |
| 강조 | `#245C4F` 한 가지부터 시작. 의미 있는 구분에만 사용 |
| 서체 | 한글: Pretendard / SUIT / Noto Sans KR 중 가용한 것. 가용하지 않으면 호환 서체로 대체 후 확인 |
| 크기 | 제목 대략 28–36pt, 본문 18–24pt, 도표·주석 대략 14–18pt(실제 발표 환경에 맞게 조절) |
| 정렬 | 대부분 왼쪽 정렬, 제목·본문의 공통 정렬축 유지 |
| 여백 | 좌우 대략 6–8%, 충분한 상하·요소 간 여백 |
| 장식 | 필요성과 의미를 설명할 수 없으면 넣지 않음 |

- 위 값은 법칙이 아니라 **출발점**이다. 높은 밀도의 기술 도표, 대형 행사장, 기관의 브랜드 가이드에 따라 달라진다.
- 일관되게 유지할 것: 서체 체계, 색상 역할, 여백, 정렬축, 출처 표기 방식. 바꿀 것: 시각적 중심, 정보량, 도해 방식, 사진 크기, 슬라이드 유형.
- 상세 디자인 토큰 및 상황별 레이아웃은 [`references/visual-system.md`](references/visual-system.md)를 참고한다. **실제 제작·템플릿 정의 시 해당 파일을 읽는다.**

### 4. 흔한 'AI 디자인 패턴'을 피한다

**기본적으로 회피**할 항목:

- 매 페이지 반복되는 **둥근 사각형 카드 3개**·동일한 2×2 카드·카드마다 그림자.
- 불필요한 제목 밑 컬러 바, 화면 가장자리 장식선, 수평·수직 강조 스트라이프.
- 기본 보라·파랑 그라데이션, 과도한 베이지톤, 유리 효과, 설명되지 않는 추상 도형.
- 전구·로켓·톱니바퀴·뇌·로봇·손잡는 사람 같은 **상투적 의미의 아이콘/이미지**.
- 슬라이드마다 동일한 길이의 3개 항목, 동일한 양의 내용, 일률적인 중앙 정렬.
- 모든 장에 억지로 시각 자료를 하나씩 넣기. **강한 텍스트만 있는 장도 허용**한다.
- 매번 과장된 표어, 영어 소제목, 'Key Takeaway' 박스, 출처 없는 인사이트를 붙이기.

**대신:** 내용에 맞는 선택을 한다. 비교는 전후 화면/비교표, 절차는 실제 스크린샷+주석, 추세는 정확한 그래프, 인과는 관계도, 개념은 정의+예시, 강조는 넓은 여백과 큰 문장. 장식 요소의 형태보다 메시지의 구조가 먼저다.

**예외:** 카드·그라데이션·아이콘 등도 실제 기능(분류, UI 재현, 브랜드 언어)이 있다면 쓴다. 'AI스럽다'는 이유만으로 좋은 정보 설계를 파괴하지 않는다.

### 5. 같은 스타일 안에서 슬라이드의 리듬을 설계한다

- 제목형·개념형·증거형·비교형·스크린샷형·프로세스형·실습형·데이터형·전면사진형·문장강조형을 **내용에 맞게 섞는다**.
- 3장 이상 연속해서 동일한 카드/열 레이아웃을 쓰는 것을 가능한 한 피한다. 일부 일관성이 학습에 도움이 되는 연속 실습 단계는 예외다.
- 슬라이드 밀도에 리듬을 둔다. 세부 설명 장 다음에는 도식·예시·질문 장으로 전환할 수 있다. 발표 시간과 청중 수준을 기준으로 **분할/병합**한다.
- 보기 좋은 템플릿에 콘텐츠를 억지로 맞추지 않는다. 정보가 많다면 슬라이드를 분리하고, 원문 전문·자세한 수치는 부록이나 발표자 노트로 보낸다.
- 가짜 스크린샷·가상 연구 그래프를 사실처럼 만들지 않는다. 실제 캡처를 받지 못했다면 `[실제 화면 삽입: 프로그램/메뉴/기대 캡처 범위]` 형태의 **편집 가능한 자리표시자**를 남긴다.
- 시각화가 필요한데 근거가 없으면 만들어내지 말고 표기한다. 인용된 사진과 도표는 사용 가능 여부와 출처를 확인한다.
- 슬라이드별 선택 예시는 [`references/storyboard-patterns.md`](references/storyboard-patterns.md) 참고. **슬라이드 기획 또는 복잡한 발표 구성 시 읽는다.**

### 6. 실제 PPTX 제작 시 기술적 품질을 확보한다

- PPTX가 목표라면 제목·본문·도형·도표를 가능한 한 **편집 가능한 요소**로 만든다. 슬라이드 한 장을 통째로 이미지로 붙여 편집이 불가능하게 만드는 것은 사용자가 요구한 경우 외에는 피한다.
- 이미지가 필수인 경우 파일로 삽입하되, 화면 캡처나 사진을 임의로 재구성하여 사실성을 훼손하지 않는다.
- 고유 도표는 정확한 수치·비율·범례·단위·출처를 표시한다. 시각적 비율이 데이터와 맞는지 확인한다.
- 서체 렌더링을 점검한다. 시스템에 없는 폰트가 다른 글꼴로 대체될 수 있으므로 텍스트 상자에 여유를 둔다.
- 선명한 화면 캡처와 해상도를 사용한다. 이미지의 종횡비를 유지하고 불필요한 늘림을 피한다.
- 사용 가능한 PPTX 생성 도구, 템플릿, 렌더러와 설치된 프레젠테이션 제작 스킬이 있다면 함께 사용한다. **이 스킬은 제작 도구를 대체하지 않는다.**
- 어떤 도구도 실행할 수 없다면 PPTX가 완성되었다고 주장하지 말고, 완성 가능한 범위의 슬라이드별 원고·디자인 명세를 제공한다.

### 7. 렌더링 후 검수하고 수정한다 (필수)

**PPTX를 실제로 만들었다면 가능한 한 모든 페이지를 이미지 또는 PDF로 렌더링**한다. 렌더러가 없으면 그 제약을 명시하고 할 수 있는 점검을 실시한다.

1. **실제 화면:** 텍스트 잘림·도형 겹침·아이콘 깨짐·이미지 오려짐·여백 불균형·작은 글씨·낮은 대비를 확인한다.
2. **전체 축소 보기:** 반복 레이아웃, 카드 남발, 모든 페이지의 동일 밀도, 쓸데없는 장식, 지나친 서체/색상 변화가 있는지 본다.
3. **내용:** 주장-근거 연결, 수치/명칭/날짜/인용의 정확성, 출처, 한글 맞춤법, 한글 줄바꿈, 실습 지시의 재현성을 점검한다.
4. **편집 가능성:** PPTX의 텍스트·도형·차트가 수정 가능한지, 자리표시자를 구분했는지 확인한다.
5. 결함이 있으면 **수정 후 다시 렌더링**한다. 렌더링·검수를 하지 않았다면 '시각적 검수 완료'라고 말하지 않는다.

- 세부 체크리스트, 판정 기준, 수정 우선순위는 [`references/quality-gates.md`](references/quality-gates.md) 참고. **최종 제작물의 QA 또는 기존 PPT 디자인 리뷰 시 읽는다.**

## 상황별 분기

- **교사 연수/소프트웨어 실습:** Technical Manual 우선. 실제 UI 캡처, 단계 번호, 입력 예시, 오류 상황, 실습 미션을 사용. 본문에 답을 모두 넣지 말고 필요한 경우 노트로 분리.
- **학술·과학 발표:** 출처·축·단위·오차·한계·개념 도식의 정확성 우선. 모호한 인과 표현 및 꾸며낸 데이터를 금지.
- **보고·회의:** 결론 먼저, 근거 데이터, 의사결정 옵션, 다음 조치·책임을 분명하게. 예쁜 인포그래픽보다 정확한 표와 해석을 우선.
- **행사·키노트:** 메시지·사진·여백을 크게 사용하되, 현장 거리에서 읽히는 크기인지 검수.
- **이미 만들어진 PPT 리디자인:** 원본 사실·순서·필수 정보는 보존. 바꾼 것과 남겨둔 것을 명료하게 설명. 본문 삭제·분할이 의미를 바꾸는 경우 피한다.
- **사용자 제공 레퍼런스:** 레퍼런스의 레이아웃 규칙을 추출해 적용. 그대로 복제하지 말고 출처·권리를 존중한다.

## 완료 조건과 응답

- PPTX 요청: 실제 PPTX 파일, 가능할 때 미리보기/PDF, 출처 또는 검증 필요 항목, 남은 스크린샷 자리표시자를 제공한다.
- 기획 요청: 슬라이드별 목표·제목·핵심 근거·권장 시각화·필요 자료가 드러나는 스토리보드를 제공한다.
- 검토 요청: 무엇이 문제인지 **구체적 슬라이드 번호와 근거**로 제시하고, 수정 문구/레이아웃/우선순위를 제안한다.
- 최종 검수 결과는 `내용 정확성 / 가독성 / 시각적 리듬 / 디자인 일관성 / 편집 가능성`으로 짧게 보고한다. **확인하지 않은 사항을 완료로 표시하지 않는다.**

## 호출 예시

- `human-crafted-slides 스킬로 90분짜리 교사 대상 AI 연수 PPTX를 만들어줘. Technical Manual 스타일에 실제 화면 자리표시자를 남겨줘.`
- `이 PPT를 분석해서 카드형 AI 디자인을 줄이고, 내용은 유지하면서 편집 가능한 슬라이드로 다시 제작해줘.`
- `먼저 20장 분량 스토리보드를 만들고 실제 근거가 없는 장을 표시해줘.`
